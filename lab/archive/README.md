# Archive

Code Flow no longer runs, kept so it can be read without digging through git history. Nothing here is installed, tested or loaded.

- **`apply-migration.js`** carried out a setup's or an update's `migration.md`, one action line at a time. Replaced 2026-10-08 by `scripts/record-originals.js`, which records the originals, and by the setup sessions, which make each change themselves. `docs/spec/setup.md` → `### Migrations` says why.
- **`migrations.js`** is `scripts/lib/machine/migrations.js` as it stood then, holding the action-line parser `apply-migration.js` used. The live file keeps `resume` and `guard`.
- **`machine-form.md`** and **`project-form.md`** were `scripts/sessions/form.md` and `project-form.md`, the setup forms' templates before 2026-10-08, with a settings key on each line and the boxes after the no-choice part. Replaced by `scripts/templates/setup-machine.md` and `setup-project.md`. `docs/spec/setup.md` → `### The forms` says why.
- **`project-overlays/`** holds `overlays.js` and its test as they stood while a project could carry its own `.flow/overlays/<name>.md`. Replaced 2026-10-12 by the global `~/.flow/skill-overlays/`: no project overlay ever existed, and a fact true for one project goes in its `CLAUDE.md`. `docs/spec/skills.md` → `### Overlays` says why.
- **`sandbox/`** holds `try.sh`, `save-computer.sh` and `test-projects/`, the pretend computer a real session ran against while nothing was installed on the real one. Moved 2026-10-14 by `fw-124`: a test from scratch runs under a scratch `--root` instead. The runs and saved computers it kept in `tmp/` were deleted, `computers/` being in the user's own GitHub repo.
- **`capture.md`** was `claude/commands/capture.md`, the `/capture` command that ran the capture sweep on request. Moved 2026-10-14 by `fw-124`: the rule file's `## Capture` already runs the sweep at each checkpoint, and `claude/commands/` is gone.
- **`domain-skills/`** is the `lab/domain-skills` submodule, a copy of the public `domain-skills` repository at `b75afbd`, without its `.git`. Moved 2026-10-14 by `fw-124` when Flow stopped serving strangers (`fw-16`). The `.gitmodules` entry is gone, and archiving the GitHub repository is the user's own step. Its `drafts/` hold `web-pages`, `excalidraw` and `chrome-extension`.
- **`apply-domain-findings/`** was `skills/dev/apply-domain-findings`, the user-only skill that read the pull requests sent to `domain-skills` and wrote the true ones into a skill. Moved 2026-10-14 by `fw-124` with `flow contribute`, which sent them.
- **`skill-repositories/`** holds what let Flow clone skill repositories and keep them current: `skills-pull.js` (the background job), `skills-update.js` (what it did to each clone and the notes it left), and whole copies of `repos.js`, `commands/skills.js` (`skills-command.js`) and `tests/skills.test.js` (`skills-command.test.js`) as they stood, with `flow skills add|drop`, the `sources` list and the `owner/repo:name` skill names. Moved 2026-10-14 by `fw-124`: `domain-skills` was the only source. The live `repos.js` keeps the util and Flow clones, and `flow skills` handles Flow's skills and the private ones. The need behind it stays: `.flow/research/skill-curation/outside-skill-repositories-dropped-in-v1.md` says what it did and what leans on it, for when the research skill is reworked.
- **`branch-storage/`** holds what let a project keep its tickets on a `flow` branch of its own repository: `store.js` (`flow store`, the move between the branch and the Flow home), and whole copies of `records-place.js` and `init.js` as they stood, with `visibility`, `addIgnore`, `copyRecords`, `ticketFolders`, the public-repository question and `flow init --private`. Moved 2026-10-14 by `fw-124`: the Flow home is now the only place, since the branch published tickets to anyone who read the repository. `lib/tickets/records.js` stays whole, because `tickets.js` and `flow-repo.js` still call it.
- **`stranger-commands/`** holds the commands that served other people's machines, with their tests in `tests/`: `restore.js`, `uninstall.js`, `update.js`, `contribute.js`, `survey.js`, plus `restore-form.js` (the list a restore ticked), `survey-machine.js` (was `lib/machine/survey.js`, the scan `flow survey` and `flow doctor` ran), `tests/old-machine.js` (the pretend old machine their tests built) and `confirm.js` (the file as it stood, with the four locks `restore` and `uninstall` took: no session open, a word typed at the terminal). Moved 2026-10-14 by `fw-124`: Flow serves the user's own machines (`fw-16`), a machine updates by a pull and `flow install`, and nothing is restored or uninstalled. The live `confirm.js` keeps `hasTerminal` and `ask`. `ticket-skills.js` lost `findAll` and `removeAll`, which only `uninstall` and `restore-form.js` called. `home/settings.json` lost the 8 deny lines for `flow restore` and `flow uninstall`.
- **`setup-and-versions/`** holds what made a machine or a project "set up" and kept both on a changelog number: `setup.js` (the setup session's checks and launcher), `sessions/{machine,project,migrate}.md`, `templates/setup-{machine,project}.md`, `tests/setup.test.js`, `record-originals.js`, `originals.js` (the machine as it was before Flow), `migrations.js`, `version.js` (the stamp), `machine.js` (the gate that refused every command without `~/.flow/version`), `CHANGELOG.md` and `upgrades/`. `before/` holds whole copies of `install.js`, `init.js`, `doctor.js`, `flow-repo.js`, `session-start.js` and `installed.js` as they stood. Moved 2026-10-14 by `fw-124`: with no stranger to restore, uninstall or migrate, the setup session had nothing left to do, and nothing needs a version number. `flow install` now makes the links, the clones and the Flow home, and `flow init` links `.flow/` and writes the template where a file is missing. The files `~/.flow/{version,run.json,originals/}` and a project's `.flow/version` stay on disk, and `IGNORED` in `flow-repo.js` still keeps them off the Flow home's repository.
- **`docs/`** holds the manuals written for strangers: the 15 pages that sat directly under `docs/` (`overview.md`, `install.md`, `sync.md`, `tickets.md` and the rest) with their `README.md`, all of `dev/` (`commands.md`, `skills.md`, `layout.md`, `trying-changes.md`) and `spec-manual.md`, which was `docs/spec/manual.md`. Moved 2026-10-14 by `fw-124`: Flow serves the user's own work first (`fw-16`), and the docs ticket (`fw-141`) decides which concise pages come back. `docs/reference/` and the other spec files stay. `dev/skills.md` and `write-skills.md` said the same rules, and `write-skills.md` now carries them alone.
- **`help/`** was `skills/tools/help/SKILL.md`, the skill that answered any question about Flow or Claude Code and fixed a problem with either, by sending the question to the docs, `flow doctor`, the logs and `/flow:research`. Moved 2026-10-14 by `fw-124` at the user's word: Flow is for them alone, any session answers from `docs/reference/` and `flow doctor`, and the description loaded into every session for nothing. Removing a skill needs `flow install`, which waits for release day (`fw-144`).
