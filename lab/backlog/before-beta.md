# Before the beta

Everything that has to be true before Flow installs on this machine and the beta starts. **Runs in the order written.** How an item is written: `docs/dev/layout.md`, the `backlog/` entry.

- [ ] **Research how issue trackers model a ticket, then decide what changes in Flow's.** Flow's tickets convert to a tracker's, never match one: a tracker with no `groundwork` status reads it as "In Progress". The beta fixes the ticket shape, and the sweep walks the ticket system, so the research comes first. Raised by the user 2026-09-28. The brief, the questions and the trackers: `lab/research/trackers.md`

- [ ] **The final sweep: finish the workflow in 5 passes.** Raised by the user 2026-09-15. Each pass ends before the next starts. It runs before the manual, because pass 2 may remove a feature a page would describe.
  1. **Walk the whole workflow from start to end through real scenarios.** Look for what breaks, what is missing and what makes no sense. Open with one run of `/doctor prompt-audit` on this repo, added in Claude Code 2.1.283: it lists stale paths, stale commands and instruction files that contradict each other. Take the report as a list of references to check, and refuse every rewrite it offers, since its idea of old wording may break `references/style.md`.
  2. **Simplify.** Find what is overbuilt, and every rule that costs flexibility. Aim for the simplest workflow a beginner can follow, and the most flexible one. A feature may shrink or go here. 2 known candidates:
     - **`docs/context/` and `docs/spec/decisions.md` overlap, and nothing routes between them.** "We use Postgres" is a durable verified fact and a locked decision at once. Recommended: delete `docs/spec/decisions.md` and split it 3 ways. Decisions that constrain implementation go to `tech.md`, product decisions to `product.md`, and refused options, bets and open questions stay in the groundwork map that produced them. Merging the folders loses more: a folder named `spec` holding a verified command breaks `name-for-content`. Walk 3 real Delapse examples first. A delete needs its own confirmation. **talk first**
     - **Context engineering**: keep what loads as small as possible, and stop the cache being invalidated when a skill loads mid-session. **talk first**
  3. **Compress every skill.** Cut the detail and explanation an agent does not need, pass after pass, until the user is happy. `/flow:groundwork` is the user's example of a skill that over-explains.
  4. **Compress and simplify the writing of every file.** Opus 5's prose is unreadable in long stretches: clauses compressed past meaning, terms used before they are defined, a path standing where an explanation belongs. A full pass per file, never patches, ruled 2026-09-05. Done: both `CLAUDE.md` files and the skills. Left: `references/`, `docs/manual/settings.md`, the 2 templates under `scripts/flow/templates/`, and `docs/dev/`, whose pages also need their structure and table of contents format redone. `/web-pages` waits for its rebuild.
  5. **Rewrite every line Flow prints, to the user and to the agent.** The hook lines, every `flow` command's output and its refusals, `flow doctor`'s report, and whatever a skill renders. Raised by the user 2026-09-20, reading the `SessionStart` lines the day they were built: the writing is unusable, and a line rewritten before this pass is rewritten twice. It runs last, because passes 1 and 2 may delete the feature a line belongs to. `references/style.md` binds prose in a file and nothing yet binds a printed line, so this pass also decides what does. **The terminal layout is part of it**, raised by the user 2026-09-26 on `flow restore machine` with 2 projects: the options, the fallback command and the paths ran together, and the first line read "Puts 1 paths". A machine with dozens of paths would be unreadable. The help and any instructions come first.

- [ ] **`scripts/` needs a cleanup and a new layout.** Every script was written for the job at hand and never reviewed as a whole, and the folder's structure confuses. Refactor for clean code without adding complexity. Raised by the user 2026-09-26. Keep every read and write of a ticket's files behind one module, so a team's tracker can later stand in for `.flow/tickets/`: `teams.md`.

- [ ] **`changes.test.js` → _2 workers at once each get only their own file_ fails about 1 whole-suite run in 8.** Never alone: 36 runs of its file in isolation passed. The failing record lists every file, the worker's own edit included, under _changed by no tool call a hook saw_. So the safety net in `buildRecord()` found no event ending after the worker's `start.json` time, which points at timestamps compared across processes and is unproven. The other flaky case, _a worker hands the parent its diff_, was a real bug, fixed 2026-09-26: `snapshot()` copied git's index with a fresh time, which turned off git's check for an edit of the same size in the same second as the commit.

- [ ] **Widen the tests over the ticket commands**, the programmatic part still uncovered. `flow install` is covered by the `flow doctor` tests. Rules and skills are tested by real work only, never by a prepared scenario, until the workflow is finished: a written-out prompt is too clean to fail, ruled 2026-09-06.

- [ ] **Plugins are a fourth install state Flow does not control**: off by default. `extraKnownMarketplaces` in the committed settings, `enabledPlugins` in `.claude/settings.local.json`, and a flip takes effect next session. `skillOverrides` is not an off switch: it leaves the commands and the hooks running. This machine's 6 plugins are part of what setup meets.

- [ ] **util: rename `git work` to `util git uncommitted`**: `send`, `get`, `ls` and `drop`. "Work" says nothing about what moves, and what moves is the changes you have not committed. Asked for by the user 2026-09-20, and Flow's pages already use the new name. The file is `commands/git/work.js`, and the label it pushes to is `refs/unfinished/<machine>/<branch>`.
